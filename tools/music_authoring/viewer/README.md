# Offline track review viewer (ATMlib2FX-3ii.6)

`tools/atm-music inspect song.json --out review.html [--audio-preview preview/] --json`
writes a standalone, offline HTML review plus a deterministic adjacent JSON.

The repository includes a ready-to-open [showcase review](../../../examples/music_authoring/showcase/review.html)
with embedded audio and the optional piezo sound profile. Its
[README](../../../examples/music_authoring/showcase/README.md#open-in-the-offline-html-track-viewer)
describes regenerating the durable HTML and JSON snapshots. The viewer's
maintained source assets are the files below; `build/` contains disposable
generated output and retained measurement evidence.

| File | Role |
| --- | --- |
| `template.html` | HTML skeleton with `__ATMLIB_CSS__`, `__ATMLIB_DATA__`, `__ATMLIB_JS__` placeholders |
| `viewer.css` | Embedded styles (inlined into the output) |
| `viewer.js` | Draws and selects the canonical payload; audio playback; no parsing/expansion |
| `piezo.js` | Optional native Web Audio coloration and raw bypass; no WAV/source changes |
| `loop.js` | Prepares one measured PCM cycle for native media looping |

`inspect.py` (package root) reads these assets, escapes the embedded JSON and
substitutes the template. Nothing here is fetched at runtime.

## One player for every song (library player)

[`examples/music_authoring/player.html`](../../../examples/music_authoring/player.html)
bundles every catalogued example composition into a single offline page with a song
selector, Previous/Next and an explicit game-context label. It is generated by
[`tools/music_authoring/library_player.py`](../library_player.py) from
[`examples/music_authoring/catalog.json`](../../../examples/music_authoring/catalog.json);
the shell assets live in [`library_player/`](../library_player/).

The library player **reuses this viewer unchanged**: for each song it rebuilds the
canonical standalone review document with the same `render_html` used by `inspect`
and embeds it in an inert JSON bundle. On selection the shell mounts exactly one
`iframe` (`srcdoc`); before mounting the next it pauses and removes the previous
document, so only one review/audio stream is ever live and nothing autoplays. Every
per-song control (piano-roll/tracker, fit/zoom/pan, lane visibility, seek/restart,
Raw/Piezo Sound) is the unchanged viewer's own. The page needs no server, network,
build directory or sibling review file. Regenerate it with:

```
python3 tools/music_authoring/library_player.py \
    --catalog examples/music_authoring/catalog.json \
    --out examples/music_authoring/player.html --json
```

The player's music files (each song's matching `preview.json` + `preview.wav`) are
maintained beside each song in `examples/music_authoring/**/preview/`; the shell
assets (`template.html`, `shell.css`, `shell.js`) live in
`tools/music_authoring/library_player/`.

## Guarantees

- **Offline / standalone.** The output loads from `file://` with no server, CDN,
  module, network request or external file. A `Content-Security-Policy` meta tag
  (`default-src 'none'`) is embedded, and audio is embedded as base64 and played
  through a `blob:` object URL.
- **No second compiler.** Every note span, pattern instance, boundary, tick,
  source pointer, digest and total comes from the canonical frontend payload.
  The JS never parses the source, expands repetition, lowers effects or
  quantizes ticks. Only the visible window is drawn (binary-searched per lane),
  and the tracker table caps its rows.
- **Inert authored data.** The payload is embedded as
  `application/json` with `<`, `>`, `&`, U+2028 and U+2029 escaped, so a
  `</script>` or HTML comment in a path/string cannot break out. All authored
  strings are rendered with `textContent`, never as HTML.
- **Review only.** Generating or opening the review never compiles, packs,
  writes or flashes FX data.
- **Visibility ≠ audio.** Lane checkboxes are labelled visibility only and never
  mute/solo; the WAV is a single mono speaker mix.

## Embedded document (the data block)

```json
{
  "payload": "atmlib-inspect", "payload_version": 1,
  "tool": {...}, "score_id": "...",
  "source_sha256": "...", "event_digest_hex": "...",
  "review": { /* canonical atmlib-review payload, verbatim */ },
  "audio": { /* descriptor, or null */ },
  "audio_diagnostics": [...],
  "capabilities": {"inspect": {"available": true}, "render": {"available": true}, "...": "..."},
  "side_effects": "Review artifact only: ..."
}
```

The adjacent JSON (same stem as `--out`, `.json`) is exactly the canonical
`atmlib-review` payload, byte-for-byte what `build --backend progmem` writes.

### Audio descriptor (embedded only when the preview matches)

`available`, `format`, `sample_rate`, `channels`, `bit_depth`, `sample_count`,
`neutral_level`, `sound_gain`, `first_music_callback_sample`/`_seconds`/
`_measured`, `effective_tick_rate`, `tick_divisor`, `ticks_per_beat`,
`beats_per_bar`, `total_ticks`, `rendered_ticks`, `truncated`,
`truncation_reason`, `song_seconds`, `post_end_dc_level`,
`post_end_is_ac_silent`, `wav_name`, `wav_sha256`, `wav_bytes`, `report_sha256`,
`matched_source_sha256`, `matched_event_digest_hex`, `limitations`,
`wav_base64`.

`effective_tick_rate` is the *actual* timer quotient `2000 / tick_divisor` (an
integer for divisor tempos such as 50 Hz, fractional otherwise). Playhead sync
uses the measured first-music-callback offset and the exact integer divider
(`tick_divisor`, base events per tick at 2000 base events/second):

```
sample(tick) = first_music_callback_sample + round(tick * tick_divisor / 2000 * sample_rate)
tick(sample) = (sample - first_music_callback_sample) / sample_rate * 2000 / tick_divisor
```

Previews rendered before `tick_divisor` existed fall back to
`tick / effective_tick_rate * sample_rate`. Devices still program the identical
integer divider (`src/osc.c:osc_set_tick_rate`); nothing about playback timing
changed.

Audition is bounded to the recorded capture (`sample_count`, or
`rendered_ticks` when truncated); regions outside it are shaded and marked, and
the seek/restart never plays past them.

The post-end DC rail (≈ −2000, zero AC, PWM stopped) is described as
acoustically silent, not as neutral 0. In-song neutral is ≈ 0 (measured steady
silence = 2 counts).

## Optional piezo preview

The **Sound** selector in Audition offers **Raw emulator** (default) and
**Piezo (approx.)**. Piezo applies a lightweight browser-only speaker coloration
to the existing mono WAV. It reduces bass, emphasizes a resonant mid/high band,
and rolls off treble. This is an uncalibrated approximation, not a measured
Arduboy piezo/enclosure response or a loudness prediction. Check final sound on
the device. Raw remains available for comparison.

The heuristic profile is:

| Stage | Setting |
|---|---|
| High-pass | 700 Hz, linear Q `1/sqrt(2)` |
| Peaking resonance | 3300 Hz, linear Q 1.4, +6 dB |
| Low-pass | 7000 Hz, linear Q `1/sqrt(2)` |
| Output trim | 0.5 linear gain, for resonance headroom |

High/low-pass Q is supplied as approximately −3.0103 dB, while peaking Q is
linear, following the [Web Audio BiquadFilterNode parameter units](https://www.w3.org/TR/webaudio/#dom-biquadfilternode-q).
The chosen response is an authored listening aid and makes no claim of hardware
calibration. No external filter implementation or speaker impulse response is
downloaded, copied or embedded.

Web Audio initializes only when the user requests Piezo. One media-element
source feeds a unity raw branch and a filtered branch; switching crossfades
between them over 20 ms. The same audio element, playback position, sample/tick
mapping and original WAV bytes/digests are retained. Once processing has been
initialized, Raw bypasses the filters. A missing/blocked Web Audio API leaves
native raw playback available and disables the Piezo option with an explanation.
Normal browser/output-device latency still applies to audible playback.

Regenerate an older review with `atm-music inspect` to include the new selector.
No FX data, generated score or AVR runtime state changes. Routing/lifecycle
checks can be run without browser dependencies:

```
node tests/music_authoring/viewer/test_piezo.mjs
python3 -m unittest discover -s tests/music_authoring -p test_inspect.py
```

Browser verification for `ATMlib2FX-3ii.9` is recorded in
[`research/music-authoring/piezo/`](../../../research/music-authoring/piezo/SUMMARY.md).
Measured results and captured screenshots stay there. Developer checks and the
browser walkthrough driver live under `tests/music_authoring/viewer/`.

## Rejected previews

`--audio-preview` requires the render report's source **and** canonical event
digests to match the current score, plus valid WAV metadata/identity. A stale or
mismatched preview is rejected (warning diagnostic, no embedded audio) instead
of letting a previous revision play. Report paths are resolved and bounded to the
requested preview directory; escaping references are refused.

## Capability report

`capabilities --json` advertises `inspect`, `render` and `wav_preview` as
available, matching the working commands. The ATMlib2FX-3ii.1
`expected/review.json` golden keeps its byte-stable embedded capabilities block
unchanged. `inspect` (and `render`) also report their own truthful availability
in their own payloads and in the embedded document's `capabilities`.
`test_inspect.CapabilityReportTests` pins the live summary against the golden.

## Recorded browser walkthrough

`tests/music_authoring/viewer/walkthrough.mjs` drives an installed local Chrome over the DevTools Protocol
against the `file://` review with no network access. It records DOM assertions,
observed resource requests, keyboard navigation, lane toggling, playback and
seek alignment, and a full-page screenshot.

```
node tests/music_authoring/viewer/walkthrough.mjs \
  examples/music_authoring/showcase/review.html \
  build/music-authoring/inspect-tests/walkthrough-audio.json \
  build/music-authoring/inspect-tests/walkthrough-audio.png
```

Override the browser with `CHROME=/path/to/chrome`. Results for the matching,
no-audio and stale-preview cases are stored under
`build/music-authoring/inspect-tests/`.
## Song looping

The Loop checkbox defaults on for scores with a whole-song loop. `loop.js`
copies exactly one musical cycle from the measured callback sample into a
browser playback WAV and uses native `audio.loop`. The original embedded capture
and its digest are retained. The cropped media clock is mapped back to capture
samples for the playhead and seek controls. Truncated or unmeasured previews
cannot loop. Turning Loop off stops at the end of that cycle; choosing a new
library song replaces the iframe and its audio.
